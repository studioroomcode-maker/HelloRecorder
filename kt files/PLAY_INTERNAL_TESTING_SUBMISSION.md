> 목적: **내부 테스트(Internal testing) 트랙에 AAB를 올려 Play 정책 심사를 실제로 통과시키는 것.**
> 빌드/서명/개인정보처리방침 본문은 `RELEASE_GUIDE.md`·`PRIVACY_POLICY.md` 참고. 이 문서는
> **Console 화면에 그대로 붙여넣을 답변과 클릭 순서, 그리고 거절 위험 자가점검**만 담는다.
> ⚠️ 표시는 **사용자(개발자)가 직접 준비/입력**해야 하는 항목.

## 0. 한눈에 보는 진행 순서

1. AAB 빌드(서명) → 2. 내부 테스트 트랙에 업로드 → 3. **앱 콘텐츠 양식 5종** 작성
→ 4. 테스터 등록 → 5. 검토 제출 → 6. 심사 결과 확인·대응

내부 테스트도 **앱 콘텐츠 양식(데이터 보안·콘텐츠 등급·타깃 연령·FGS 선언 등)을 통과해야** 게시됩니다.
이 단계에서 정책 스캔이 실제로 돌기 때문에, #3의 진짜 목적(정책 통과 검증)이 여기서 달성됩니다.

## 1. 업로드 전 빌드 체크 (코드 측 — 대부분 완료됨)

| 항목 | 상태 | 비고 |
|---|---|---|
| `applicationId` = `com.studioroomkr.hellorecorder` | ✅ | com.example 아님 |
| `targetSdk` 36 | ✅ | Play 최소 요건 충족 |
| `versionCode` = 1 | ✅ | 첫 업로드 OK. **재업로드마다 +1 필수** |
| 서명 설정 | ✅ | `keystore.properties` + `.jks` 만 준비하면 자동 서명 |
| `allowBackup=false` | ✅ | 녹음 클라우드 백업 차단 |
| 온디바이스 크래시 로그(#2) | ✅ | **외부 전송 없음 → Data Safety "수집 안 함" 유지에 영향 없음** |

**빌드 명령**
```
cd android
./gradlew :app:bundleRelease        # 산출물: app/build/outputs/bundle/release/app-release.aab
./gradlew :app:signingReport         # 서명 확인
```
⚠️ `keystore.properties`·`release.jks` 가 없으면 미서명으로 나옴 → Play 업로드 불가. `RELEASE_GUIDE.md` C-1 참고.

## 2. 앱 콘텐츠 양식 — 그대로 붙여넣을 답변

### 2-1. 데이터 보안 (Data safety)
경로: **앱 콘텐츠 → 데이터 보안**

- **"앱이 사용자 데이터를 수집하거나 공유합니까?"** → **아니요 (No)**
  - 근거: 녹음·위치·설정·**크래시 로그 모두 기기 내부에만 저장, 외부 전송 0**. Google 정의상 '수집=기기 밖 전송'.
  - 사용자가 공유 시트로 직접 내보내는 것(녹음/오류로그 공유)은 '공유(share)'에 **불포함**(사용자 행위).
- 이어 나오는 보안 관행 2문항:
  - **"수집한 데이터가 전송 중 암호화됩니까?"** → 데이터 수집 없음 → 해당 없음/그대로 진행.
  - **"사용자가 데이터 삭제를 요청할 수 있습니까?"** → **예** (앱 내 파일 삭제 + 앱 삭제 시 전부 제거).

### 2-2. 포그라운드 서비스 권한 선언 (필수 — 거절 단골)
경로: **앱 콘텐츠 → 포그라운드 서비스 권한 (Foreground service permissions)**

- 선언 권한: **FOREGROUND_SERVICE_MICROPHONE**
- **용도 설명(붙여넣기, KO):**
  > HelloRecorder는 사용자가 직접 시작한 본인의 녹음(회의·강의·개인 메모)을 화면이 꺼져 있거나
  > 다른 앱을 사용하는 동안에도 끊김 없이 이어가야 합니다. 이를 위해 마이크 포그라운드 서비스와
  > 지속 알림을 사용합니다. 녹음은 사용자가 명시적으로 시작한 경우에만 동작하고, 동작 중에는
  > 항상 지속 알림이 표시되며, 오디오는 기기 내부에만 저장되고 외부로 전송되지 않습니다.
- **용도 설명(EN):**
  > HelloRecorder captures the user's own recordings (meetings, lectures, personal memos) and must
  > continue while the screen is off or the user is in another app. It uses a microphone foreground
  > service with a persistent notification. Recording runs only after the user explicitly starts it,
  > a persistent notification is always shown while active, and audio is stored only on the device and
  > never transmitted.
- ⚠️ 일부 계정은 **사용 시연 영상 링크**를 요구함 → 녹음 시작 시 알림이 뜨는 30초 화면녹화를 YouTube(비공개)로 올려 링크 준비.

### 2-3. 콘텐츠 등급 (Content rating) 설문
경로: **앱 콘텐츠 → 콘텐츠 등급**
- 카테고리: **유틸리티/생산성/도구** 선택.
- 폭력·성적 콘텐츠·욕설·도박·약물 등 **전부 "아니요"** → 결과: 전체 이용가(Everyone/3+).
- 이메일: `contact@studioroomkr.com` (또는 studioroom.skb@gmail.com).

### 2-4. 타깃 연령층 (Target audience and content)
- 대상 연령: **만 13세 이상** (아동 대상 아님 → "아동 포함 안 함").
- '아동에게 어필하는 디자인' → **아니요**.

### 2-5. 개인정보처리방침
경로: **앱 콘텐츠 → 개인정보처리방침**
- 게시본은 `docs/privacy-policy.html` (한/영 한 페이지). GitHub Pages 로 게시한다.
  - 저장소 Settings → Pages → Source: `main` 브랜치 `/docs` 폴더 → Save
  - 게시 주소: `https://studioroomcode-maker.github.io/HelloRecorder/privacy-policy.html`
  - ⚠️ 파일이 **main 에 있어야** 게시된다(v2 브랜치에만 있으면 404 — PR #3 병합 필요).
  - ✅ 크래시 로그 조항 추가 완료(2026-07-20) — `2. 라. 오류 진단 기록`. 기기 내부 저장·외부
    전송 없음을 명시했고 Data Safety '수집 안 함' 답변과 어긋나지 않는다.

## 3. 🚨 스토커웨어/감시 정책 자가점검 (이 앱 최대 거절 위험)

상시 녹음 앱은 Google **부적절한 콘텐츠·스토킹 정책** 스캔 대상. 아래 전부 충족해야 안전:

| 점검 | 현재 | 조치 |
|---|---|---|
| 마이크 접근 전 사전고지+동의 | ✅ ConsentActivity | 그대로 |
| 녹음 중 지속 알림 표시 | ✅ RecordingService(setOngoing) | 그대로 |
| 스토어 설명/스크린샷에 '몰래·도청·감시·상대방 녹음·spy·hidden' 표현 없음 | ✅ STORE_LISTING 가이드 | ⚠️ 스크린샷 캡션도 재확인 |
| 앱 아이콘/이름이 위장(가짜 계산기 등)이 아님 | ✅ | 그대로 |
| **프라이버시 모드가 녹음 알림 문구를 숨김** | ✅ **해결(2026-06-23)** | 아래 ★ |

### ★ 프라이버시 모드 — 해결됨 (2026-06-23)
이전엔 '프라이버시 모드' ON 시 알림 제목이 "녹음 중"→"서비스 실행 중"으로 바뀌고 본문이 비어
녹음 표시를 가렸음(감시앱 스캔 오해 위험).
**조치:** `RecordingService`에서 프라이버시 모드 분기를 제거 → **항상 "녹음 중 · 소리가 감지될 때만
저장됩니다"** 로 표시. 프라이버시 모드는 이제 **화면 캡처 차단·최근앱 가림만** 담당한다. 보안 섹션
안내 문구·번역도 실제 동작에 맞춰 정정함. → 이 항목은 정식 출시 심사에서도 안전.

## 4. 내부 테스트 트랙 설정 (⚠️ 사용자 작업)

경로: **테스트 → 내부 테스트 → 새 버전 만들기**
1. 위 `app-release.aab` 업로드.
2. 출시명/출시 노트 입력(간단히 "최초 내부 테스트").
3. **테스터**: 이메일 목록 또는 Google 그룹 추가(본인 계정 `studioroom.skb@gmail.com` 포함).
4. "검토 후 출시" → 제출.
5. 테스터에게 **옵트인 URL** 공유 → 기기에서 설치 확인.

> 내부 테스트는 보통 검토가 빠르지만(수 시간~1일), **앱 콘텐츠 양식 미완성 시 게시 차단**됨.

## 6. 거절 시 대응 (심사 노트에 미리 적어둘 문구)

거절/문의가 오면 또는 제출 시 리뷰 노트에 첨부:
> 본 앱은 사용자가 자신의 회의·강의·개인 메모를 녹음하기 위한 생산성 도구입니다. 마이크 접근 전
> 사전 고지와 동의를 받고, 녹음 중에는 항상 지속 알림을 표시합니다. 모든 데이터는 기기 내부에만
> 저장되며 외부로 전송되지 않습니다. 위치는 '사용 중에만' 권한으로 선택 기능에서 구역 판단에만
> 쓰고 저장·전송하지 않습니다. 타인을 몰래 감시·도청하는 용도를 명시적으로 금지하고 있습니다.

가장 흔한 거절 사유 3가지와 대응:
1. **FGS 마이크 정당성 부족** → 2-2 설명 + 시연 영상 제출.
2. **감시앱 의심** → 3번 자가점검(특히 ★ 프라이버시 모드) 정리 후 재제출.
3. **개인정보처리방침 URL 무효/누락** → 공개 URL 게시 확인.
